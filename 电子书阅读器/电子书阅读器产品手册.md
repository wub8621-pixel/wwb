# 电子书阅读器 · 产品手册

> 版本：1.0.0
> 定位：把本地 txt 文本一键排版成可阅读、可下载的 EPUB 电子书。

---

## 一、产品简介

电子书阅读器面向“手里有一堆 txt，想变成像样电子书”的场景。上传或指定目录后，它会自动完成：

- 识别文件编码（UTF-8 / GB18030 / GBK / Big5），统一换行
- 按正则切分章节；遇到乱序、乱码、章节过少时，再用大模型兜底识别
- 提取书名、作者、简介；缺失时由大模型补全
- 生成封面、目录和排版样式，打包成标准 EPUB

一个 txt 生成一本电子书，默认输出到 `output/`。

---

## 二、适用场景

| 适合 | 不适合 |
|---|---|
| 本地 txt 小说、文稿批量转 EPUB | 扫描版 PDF、图片文字（不做 OCR） |
| 章节格式不统一、排版混乱的文本 | 需要公网多用户、鉴权与配额的服务 |
| 需要封面、目录、可直接导入阅读器的成品 | 对版式做精细手工排版的出版物 |

## 三、三种使用方式

### 3.1 网页（推荐）

1. 先启动接口服务：`python -m ebook.api`
2. 再启动页面：`python -m ebook.ui`
3. 浏览器打开 <http://127.0.0.1:7882>

页面特性：

- **上传即转换**，没有“开始转换”按钮
- 可一次选择多本 txt（默认上限 20 本）
- “允许 LLM 兜底”开关：关闭后只跑正则，速度更快
- 右侧直接展示封面、书名/作者、章节标签和正文预览
- “护眼模式”：暖纸色底、低对比、衬线正文，只改变样式，不重新转换
- 转换完成后可直接下载 EPUB

### 3.2 HTTP 接口

启动：`python -m ebook.api`，默认地址 `http://127.0.0.1:7881`。

| 方法 | 路由 | 说明 |
|---|---|---|
| GET | `/` | 跳转到接口文档 |
| GET | `/docs` | 交互式接口文档，可直接试调 |
| GET | `/health` | 存活检查、模型信息、LLM 是否可用 |
| POST | `/api/convert` | 上传一个 txt，同步返回 EPUB 文件 |
| POST | `/api/convert/batch` | 上传多个 txt，返回逐本结果与下载链接 |
| GET | `/api/runs/{run_id}` | 查询某次运行的结果 |
| GET | `/api/download/{run_id}/{filename}` | 下载已生成的书 |

```bash
curl http://127.0.0.1:7881/health

curl -o 书名.epub -F "file=@/path/to/书名.txt" \
  http://127.0.0.1:7881/api/convert

curl -F "files=@一本.txt" -F "files=@另一本.txt" \
  http://127.0.0.1:7881/api/convert/batch
```

单本转换的响应头包含 `X-Run-Id`、`X-Chapters`、`X-Repaired`，便于追踪。

### 3.3 命令行

```bash
cd 电子书阅读器

.venv/bin/python -m ebook.cli /path/to/txt目录
.venv/bin/python -m ebook.cli /path/to/目录 --recursive   # 含子目录
.venv/bin/python -m ebook.cli /path/to/目录 --no-llm      # 只用正则
.venv/bin/python -m ebook.cli /path/to/目录 --json        # JSON 结果
```

不传目录时读取 `runtime.default_input_dir`；两者都空会报错退出（返回码 2）。

## 四、处理流程

```
读取文件 → 编码识别与换行统一 → 正则切章 → 质量判定
        →（异常时）LLM 兜底 → 元数据提取/补全 → 生成封面与目录 → 写 EPUB
```

质量判定关注四件事：乱码比例、空白行比例、章节序号是否倒序、长文本章节数是否过少。任一项超阈值才会调用大模型，正常文本不会产生额外费用。

## 五、配置说明

所有可调参数都在 `config/settings.yaml`，业务代码不写死任何参数。本机私有覆盖可放 `config/settings.local.yaml`（已在 `.gitignore` 中）。

| 配置组 | 作用 | 常用项 |
|---|---|---|
| `model` | 大模型端点 | `base_url`、`name`、`api_key_env`（只存环境变量名） |
| `runtime` | 运行与日志 | `log_level`、`log_retention_days`、`output_dir` |
| `chapters` | 章节识别 | `patterns`、`max_title_chars`、`min_chapters` |
| `quality` | 兜底触发阈值 | `garbled_ratio`、`blank_ratio` |
| `llm_fallback` | 模型兜底范围 | `enabled`、`max_input_chars`、`max_chapters` |
| `metadata` | 书名/作者提取 | `author_patterns`、`description_max_chars` |
| `epub` | 成品样式 | `language`、封面尺寸/配色/字体 |
| `server` | HTTP 服务 | `host`、`port`、`max_upload_mb`、路由前缀 |
| `frontend` | 页面 | `host`、`port`、`api_base`、`preview_chars` |

密钥只以环境变量名形式保存，例如：

```bash
export ANTHROPIC_AUTH_TOKEN="你的密钥"
```

## 七、质量保障

内置质检脚本：

```bash
.venv/bin/python -m eval.check_epub --epub-dir output --source-dir /path/to/txt目录
```

| 指标 | 含义 | 期望 |
|---|---|---|
| 章节数 | 产物中的正文文档数 | 与预期一致 |
| 覆盖率 | 原文字符在产物中的保留比例 | 100% |
| 缺字 | 原文有、产物没有的字符数 | 0 |
| 乱码 | 私用区/替换符字符数 | 0 |
| EPUBCheck | W3C 结构合规（需 java + epubcheck.jar） | 0 errors / 0 warnings |

当前样本实测：覆盖率 100%、缺字 0、乱码 0；EPUBCheck 曾通过 0 错误 0 警告，最近一次复测因本机缺少 `epubcheck.jar` 未运行。

## 八、常见问题

| 现象 | 处理 |
|---|---|
| 页面顶部提示“后端不可用” | 先运行 `python -m ebook.api`，确认 7881 端口可用 |
| 封面中文显示为方块 | 在 `epub.cover.font_path` 指定系统中文字体路径 |
| 章节切得太碎 | 调小 `chapters.max_title_chars` |
| 该切的章节没切出来 | 在 `chapters.patterns` 补正则；仍不行时检查是否触发了兜底 |
| 模型调用过于频繁 | 调大 `chapters.min_chapters`，或放宽 `quality.*` 阈值 |
| 书名/作者不正确 | 调整 `metadata.author_patterns`；书名默认取文件名 |
| 上传报 413 | 调大 `server.max_upload_mb` |
| 端口被占用 | 修改 `server.port` / `frontend.port` |

## 九、已知限制

- 只处理纯文本，扫描版 PDF/图片不做 OCR
- 正文超过 `llm_fallback.max_input_chars` 时只修前一段，剩余并入最后一章
- 书前目录页会被当作正文，暂不剔除
- 中文数字只解析常见写法（一～万）
- 封面依赖系统中文字体，找不到时中文可能显示为方块
- 覆盖率是字符级召回，不校验顺序与段落结构；版式合规交给 EPUBCheck
- HTTP 服务默认只监听本机且无鉴权，不要直接暴露公网
- `output/runs/` 会随请求累积，需要定期清理
